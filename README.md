# OpenAI Docs Scraper

Mirrors the OpenAI API reference from developers.openai.com as individual Markdown files.

## Prerequisites

- Python 3.10+
- [just](https://github.com/casey/just) (optional, for convenience commands)

No browser is required — discovery runs over plain HTTP.

## Setup

```bash
pip install -r requirements.txt
```

Or with just:

```bash
just install
```

## Usage

Run the scraper:

```bash
python scrape_openai_docs.py
# or
just scrape
```

This will:
1. Discover every page from the site's two manifests
2. Fetch each page's raw Markdown
3. Rewrite cross-references to point at local files
4. Save files to `docs/` and delete any that the site no longer publishes

## How discovery works

The site publishes two machine-readable manifests, and neither is a superset of
the other:

| Manifest | Serves | Covers | Misses |
|---|---|---|---|
| `/api/reference/index.md` | `<path>/index.md` | the current resource tree (395 pages) | streaming/websocket event pages, section overviews |
| `/api/reference/llms.txt` | `<path>.md` | event pages, overviews, titles and descriptions | still lists pre-restructure `resources/organization/*` paths |

The scraper takes the union of both, then drops the retired pages at fetch
time: the stale `organization/*` entries now serve a short "generated by
Stainless" placeholder instead of real content, which is detected and skipped
rather than written. That currently yields **413 real pages** out of 486
discovered.

## Notes on output

**Internal AST stripping.** The streaming and websocket event pages inline the
documentation generator's internal declaration graph (`"kind":
"HttpDeclProperty"`, `"oasRef"`, …) once per event, which pushes a single page
past 20 MB. Those fenced blocks are dropped; every heading, description, schema
name and example payload is kept. `responses/streaming-events.md` goes from
14.7 MB to 24 KB with all 53 events intact. Pass `--keep-internal-ast` to
disable. If OpenAI fixes the leak upstream the filter simply stops matching.

**Link rewriting.** The docs cross-reference each other through legacy
`/docs/api-reference/<slug>` paths that bear no mechanical relation to the
current tree (`runs/submitToolOutputs`, `files/retrieve-contents`). Rather than
guess at an alias table, the scraper follows the site's own redirects for those
slugs, which is authoritative — a naive path match would mislink
`files/retrieve-contents` to `files/retrieve_content` instead of
`files/retrieve`. About 1,330 of ~1,390 cross-references resolve to local
files; the rest are slugs that are dead upstream and are left as absolute URLs.
Nothing relative is left dangling.

## Updating openai-markdown-docs

After scraping, export the docs to the main repository:

```bash
just export
```

This copies `docs/` (excluding `docs/plans/`) to `../openai-markdown-docs/api-reference/`.

## Commands

| Command | Description |
|---------|-------------|
| `just install` | Install Python dependencies |
| `just scrape` | Discover and fetch everything |
| `just scrape-cached` | Re-fetch using the cached page list |
| `just scrape-missing` | Fetch only pages absent from `docs/` |
| `just clean` | Remove generated docs and the page cache |
| `just export` | Copy docs to openai-markdown-docs repo |

Useful flags: `--jobs N` (parallel fetches, default 4), `--max-failures N`
(exit non-zero above the threshold, default 10), `--no-prune`,
`--keep-internal-ast`.

## CI Workflow

A GitHub Actions workflow (`.github/workflows/scrape.yml`) runs daily at 06:00 UTC and pushes updated docs to [openai-markdown-docs](https://github.com/razmser/openai-markdown-docs).

The workflow:
1. Checks out this repo and sets up Python 3.12
2. Clones `openai-markdown-docs` using a PAT
3. Runs the scraper, including discovery
4. Exports docs and commits any changes

Discovery runs on every scheduled run. It previously did not, and the frozen
page list meant newly published endpoints could never reach the docs repo. The
scraper exits non-zero if more than `--max-failures` pages fail, which aborts
the job before the export step so a partial mirror is never published.

### Secret setup

The workflow requires a `DOCS_REPO_TOKEN` repository secret — a fine-grained personal access token with **contents:write** permission on the `openai-markdown-docs` repo.
